# Input path review: XTest pointer acceleration, sub-pixel accumulation, per-event flush

XTest relative motion goes through the X server's pointer acceleration for the XTest virtual device; sub-pixel deltas are accumulated and truncated; every event is flushed separately. Probably small next to the display path; look after the display work.

Checked 2026-09-18: `xset q` on :80 reports pointer acceleration 0/1, threshold 0, and the XTEST pointer has no libinput accel properties, so XTest relative motion is 1:1 pixels. Acceleration is not a factor. Remaining candidates: truncation of sub-pixel deltas (max 1 px lag), and flush-per-event round trips on the display thread.
