# Input path review: XTest pointer acceleration, sub-pixel accumulation, per-event flush

XTest relative motion goes through the X server's pointer acceleration for the XTest virtual device; sub-pixel deltas are accumulated and truncated; every event is flushed separately. Probably small next to the display path; look after the display work.

Checked 2026-09-18: `xset q` on :80 reports pointer acceleration 0/1, threshold 0, and the XTEST pointer has no libinput accel properties, so XTest relative motion is 1:1 pixels. Acceleration is not a factor. Remaining candidates: truncation of sub-pixel deltas (max 1 px lag), and flush-per-event round trips on the display thread.

## 2026-09-18: measured relative path on the owner's setup

- Hyprland 0.56.2 (`efb509937800`), flat acceleration, sensitivity 0;
  fullscreen F1 at 3840×2160@120, scale 1.25, logical 3072×1728;
  source `:80` at 3840×2160. Injected `EV_REL`/`SYN_REPORT` into the existing
  Logitech G502 X Plus device; observed `WAYLAND_DEBUG` and `XQueryPointer`.
- One count arrived as `delta == delta_unaccel == 1.0`, and advanced
  `wl_pointer.motion` by one logical unit, **not 0.8**. Hyprland does not
  divide relative deltas by output scale ([matching implementation](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/managers/input/InputManager.cpp)).
  `window_to_source_delta` added a 1.25 multiplier: eight +1 events landed
  at offsets `1,2,3,5,6,7,8,10`; negative and vertical motion behaved likewise.
  Removed that transform from relative forwarding in `src/display/input.rs`.
  Kept `event.delta`, since the fields were equal.
- After the change, all tested ±1 events produced exactly ±1 source pixel.
  A 400-event +1 stream paced at 1 kHz produced 400 pixels (previously 500).
  The datagram route bypasses Sizer and produced 400 in both builds. Both
  reached the final position at the first query ~1 ms after the last injection,
  with no further motion over 20 ms. Artificial socket deltas of 0.25 gave
  offsets `0,0,0,1`: fractions are retained; the corrected device path has none.
- Correction: x11rb 0.14 XTest motion has no reply; `flush()` writes buffered
  requests without an acknowledgement round trip. No accumulating backlog
  was observed at 1 kHz. No XTest or batching changes are warranted.

Relative/XTest concerns are ready to close with the working-copy fix. This does
not establish the cause of normal HoN cursor lag: `cursor_visible=true` during
the checks selects **absolute** forwarding by default, so tests used `set confine
on` and `set relative on`. Unmeasured: sensor/USB, ordinary absolute forwarding,
HoN processing, individual flush cost and input-to-photon latency.

Reviewer note: the absolute path (cursor visible) still maps logical window
position to source pixels, so it moves 1.25 source px per count at scale 1.25
while the relative path now moves 1.0. That is inherent: absolute must cover the
whole source, relative must deliver counts. A game that toggles cursor
visibility will feel the difference.

Closed: Relative motion forwards raw counts; window-to-source delta scaling removed (was 25% gain at scale 1.25). XTest accumulation and flush verified exact at 1 kHz.
